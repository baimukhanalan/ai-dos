# Внешний воркер DamuMed

Заводит записи AI Dos в веб-интерфейсе DamuMed, пока официального API нет. Работает как обычный сотрудник регистратуры: открывает браузер, выбирает пациента, находит график врача, кликает свободный слот, заполняет форму и **перечитывает результат**.

Это отдельный пакет: он не собирается вместе с приложением и не выкладывается на Vercel. Headless-браузеру нужен постоянный хост, а не serverless-функция.

## Перед запуском

1. **Разрешение оператора МИС.** Автоматизация чужой государственной системы под учётной записью клиники — вопрос к владельцу DamuMed и к договору клиники. Получите письменное согласие до боевого запуска.
2. **Отдельная учётная запись** для робота, с правами только на запись на приём. Так действия робота отличимы от действий людей в журнале МИС.
3. **Пароль здесь не хранится.** Вход выполняется руками один раз, дальше используются cookies сессии.

## Установка

```bash
cd workers/damumed && npm install && npx playwright install chromium
```

```bash
cp .env.example .env
```

Заполните `AIDOS_BASE_URL` и `MIS_WORKER_SECRET` (тот же секрет, что в переменных окружения AI Dos), проверьте `DAMUMED_BASE_URL` — адрес регистратуры отличается по регионам.

В самом AI Dos должно быть выставлено `MIS_ADAPTER=remote`, иначе очередь обслуживается внутри приложения и `/api/mis/queue` ответит 409.

## Шаг 1. Сессия

```bash
npm run login
```

Откроется браузер. Войдите своими руками; как только увидите рабочий стол регистратуры, воркер сохранит `storage-state.json`. **Храните этот файл как секрет** — в нём действующая сессия.

## Шаг 2. Сверка селекторов

Привязка к интерфейсу собрана по видимым русским подписям («Тип оплаты:», «Услуга:», «Сохранить») и живёт в одном файле — [`src/ui.ts`](src/ui.ts). Подписи взяты со скриншотов рабочего интерфейса; **на живом стенде их нужно подтвердить**:

```bash
npm run discover "ІЗТІЛЕУ А.Б."
```

Команда откроет браузер, пройдёт по рабочему столу, странице поиска графиков и дневной сетке, а в `artifacts/` положит для каждой страницы:

- `discover-*.txt` — читаемый список полей с подписями рядом;
- `discover-*.json` — то же с id, name и классами;
- `discover-*.png` — снимок экрана.

Если поле не находится — поправьте подпись в `LABELS` или локатор в `ui.ts`. Больше нигде селекторов нет.

## Шаг 3. Чтение расписания (парсер)

```bash
npm run parse 12.08.2026 -- --slots
```

Снимает все графики на дату со всех страниц списка и, с `--slots`, дневную сетку по каждому графику со свободными местами. Результат — `artifacts/schedules-12-08-2026.json`. Это чтение: в чужой системе ничего не меняется.

## Шаг 4. Сухой прогон

```bash
npm run run:dry
```

Берёт пачку из очереди AI Dos, доходит до заполненной формы записи и **не нажимает «Сохранить»**. Отчёт в AI Dos не отправляется. Так проверяется весь путь без риска завести лишний приём.

## Шаг 5. Боевой запуск

```bash
npm run run:once   # один прогон
npm run run        # непрерывный цикл
```

Держите процесс под systemd, pm2 или в контейнере — воркеру нужен постоянно работающий хост.

## Как исходы попадают в AI Dos

Воркер отчитывается в `/api/mis/results`, а AI Dos решает судьбу записи (`decideSyncOutcome`):

| Что случилось | Отчёт | Что делает AI Dos |
|---|---|---|
| Записали и перечитали | `synced`, `verified: true` | запись помечена перенесённой |
| Записали, но не перечитали | `synced`, `verified: false` | **повтора не будет** — иначе в МИС появится дубль; уходит задача сотруднику |
| Сессия истекла | `unavailable` | попытка не засчитывается, очередь вернётся через час |
| Пациент не найден | `failed`, `patient_not_found` | без повтора, задача сотруднику |
| Услуга не найдена | `failed`, `service_not_found` | без повтора, задача сотруднику |
| Слот уже заняли | `failed`, `slot_taken` | без повтора, задача сотруднику |
| График не найден | `failed`, `schedule_not_found` | повтор с нарастающей задержкой |
| Прочее | `failed`, `adapter_error` | повтор с нарастающей задержкой |

Число попыток считает сервер: воркер его не передаёт и не может обнулить бюджет повторов.

## Границы

- **Своё расписание в AI Dos остаётся источником правды.** Воркер переносит уже подтверждённую запись, а не бронирует «наугад».
- **Идентификатора записи DamuMed в интерфейсе нет**, поэтому внешним ключом служит координата слота: `damumed:<график>|<дата> <время>`. По ней запись находится заново. Если в талоне обнаружится номер — замените `externalKey` в `src/text.ts`.
- **Пациент не заводится автоматически.** Если его нет в МИС, воркер честно сообщает `patient_not_found` и зовёт человека.
- **Нагрузка.** Между действиями стоит пауза (`DAMUMED_ACTION_DELAY_MS`), пачка ограничена (`DAMUMED_BATCH_LIMIT`), параллельных сессий нет.
- **Персональные данные.** В журнал пишется только идентификатор записи и фамилия с инициалами. Наружу из AI Dos уходят имя, телефон и дата рождения — без ИИН и медицинских подробностей.

## Чего пока нет

- **Загрузка расписания обратно в AI Dos.** `npm run parse` кладёт JSON в файл; чтобы booking-flow предлагал живые слоты DamuMed, нужен приёмный маршрут и таблица внешних слотов — это отдельный шаг.
- **Отмена и перенос.** `cancelBooking` в `src/booking.ts` написан, но в очередь отмены AI Dos пока не отдаёт: `/api/mis/queue` выдаёт только создание.
- **Автовосстановление сессии.** Истёкшую сессию восстанавливает человек командой `npm run login`; воркер это состояние распознаёт и не тратит попытки.
